## The concept

Cognitive load theory already explains why long, unbroken study sessions
wear people out faster than short ones — working memory can only hold a
handful of things at once. Running multiple AI agents or projects at the
same time taxes that exact same limited resource, just with a different
kind of item filling it up.

It isn't the work itself. An agent handling a task is, by definition,
work you aren't doing. What fills working memory instead is *tracking
state*: which agent is on which step, whether the last one finished
cleanly or needs a look, what you asked for versus what might have
drifted, and the background hum of "is that other one still running?"
None of that shows up as visible output, so it's easy to undercount —
but it occupies the same limited slots as everything else you're holding
in mind, which is exactly why a wearable tracking stress can pick it up
even when the actual typing and thinking you're doing has gone down.

Extraneous load (effort spent on the format of a task rather than the
task itself) is the useful frame here: reviewing five parallel agent
threads is mostly extraneous load — none of that context-switching
teaches you anything or moves any project forward — while the germane
load (the part that's actually building understanding) barely changes
per agent added.

## Why it matters

This is the direct root cause behind the "more tools, more stress" thing
you noticed on your own tracker: it's not a sign anything is going
wrong, it's cognitive load theory doing exactly what it predicts when
you multiply the number of things being tracked at once, independent of
whether each individual thing is easy. It's also the setup for
designing-boundaries-with-always-on-agents — once the cause is "state
tracking," the fix is reducing how much state you have to hold, not
just gritting through more of it.
